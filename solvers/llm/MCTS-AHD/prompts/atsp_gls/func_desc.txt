The `heuristics` function takes as input a directed distance matrix of an Asymmetric TSP instance, where distance_matrix[i][j] is the cost of travelling FROM city i TO city j and is generally NOT equal to distance_matrix[j][i]. It returns prior indicators of how bad it is to include each directed arc in a solution. The return is of the same shape as the input. The guided local search penalises the tour arc with the highest value of heuristics[i][j] / (1 + times_already_penalised[i][j]), so the returned matrix decides which arcs the search abandons first. Only the relative magnitudes matter; the matrix is never added to the tour cost. Note that arc (i, j) and arc (j, i) are different arcs and may deserve different values. The instances are not all alike: some have arc costs spread over orders of magnitude, others are nearly flat, with every cost inside a factor of two of the median and a few percent of the arcs costing exactly zero. A rule that reads the matrix it is given and adapts to which of these it is facing will do better than one tuned for either alone. Use efficient vectorized NumPy implementations (e.g. broadcasting, np.min(axis=...), np.mean(axis=...)) without explicit Python loops. Do NOT use for loops over matrix indices as they cause execution timeouts.
